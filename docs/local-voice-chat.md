# Local Qwen chat and Thai/English voice

`@bot ข้อความ` and `/chat message` use Ollama (`qwen3:4b`) for a reply, post
the text, then speak through Wayu in your current voice room. Without a voice
room, you receive text only. If the bot occupies another room it explains why
it cannot speak and stays there. Bots, webhooks and DMs are ignored.

The bot keeps up to ten conversation pairs per server + text channel + user
in RAM. History expires after 30 minutes of inactivity or a restart.
`/chat-reset` clears your history in the current text channel, including a
reply currently being generated. There is one active chat job across the bot
and at most five waiting. Input is limited to 2,000 characters and speech to
1,000, using sentence boundaries when possible. Longer text replies are split
across Discord messages.
Code blocks, links and Markdown decorations are removed from speech.

## Chat personality

Both `/chat` and explicit mentions share the system prompt in
`src/features/chat/persona.ts`. The bot is a cheerful, warm, playful female
companion with occasional gentle affection, and no fixed name. In Thai it
calls itself “เรา” and the user “เธอ”, adapting forms of address when asked.
It keeps casual replies to roughly 1–3 sentences, expands when useful, and
reduces teasing when the user is serious or upset. It avoids profanity,
possessiveness, invented memories, and claims of actions it cannot perform.
English conversations receive English replies; speech-friendly wording,
minimal emoji, and no stage directions keep voice replies natural.

Edit `CHAT_SYSTEM_PROMPT` to adjust the personality and its short examples.
Restart the bot after editing (rebuild first when running compiled output).
Use `/chat-reset` or a fresh conversation when evaluating changes so earlier
replies do not influence the new tone. This changes wording, not the configured
TTS voice, and adds no per-server settings or new commands.

To review the tone, try a greeting, playful banter, a help request, an expression
of tiredness, an unknown personal fact, and an English question. Check that
the answers remain useful, vary their phrasing, and do not add affection to
every response. Try both entry points and listen to a Thai voice reply.

## Install on Windows

Install Python 3.10, Git and [Ollama](https://ollama.com/download/windows).
Python 3.10 avoids building tltk's older scikit-learn dependency from source on Windows.
The scripts create a separate CPU-only Python environment under `.local-voice/`;
they do not install Python packages into your system environment.

From the repository root in PowerShell:

```powershell
.\scripts\local-voice.ps1 setup
.\scripts\local-voice.ps1 download
.\scripts\local-voice.ps1 test
.\scripts\local-voice.ps1 start
Invoke-RestMethod http://127.0.0.1:8788/health
```

The download step pulls Qwen, downloads Wayu weights, and warms Thai, English
and mixed text to cache frontend assets. Ollama must be running for its pull
command. The service loads the model once with `device="cpu"` and reads local
weights with Hugging Face/Transformers offline mode enabled. Both inference
services use loopback addresses. Setup/download need internet; Discord always
needs internet.

Add these settings to the bot's `.env` (the defaults work without adding them):

```dotenv
OLLAMA_URL=http://127.0.0.1:11434
OLLAMA_MODEL=qwen3:4b
LOCAL_TTS_URL=http://127.0.0.1:8788
LOCAL_TTS_VOICE=f_young_clear
```

Chat always selects local Wayu TTS, independently of the existing `/say`
provider. To use Wayu for `/say` too, set `AI_TTS_PROVIDER=local` and redeploy
commands to refresh its voice choices. `LOCAL_TTS_VOICE` takes precedence for
local synthesis; a previous `AI_TTS_VOICE=alloy` cannot break it.
The Python server inherits `LOCAL_TTS_VOICE` from its shell environment; it does
not read the bot's `.env`. The bot sends its configured voice with every request.

Wayu's inference code is Apache-2.0, while its model weights are
[CC-BY-NC-4.0, with attribution required and no commercial use](https://github.com/wayu-research/wayu-tts-inference).
Voice is machine-generated by Wayu-Paxa-TTS-Edge, from Wayu Research.
The pinned inference revision is in `services/local-tts/requirements.txt`.
For English words outside the dictionary, the upstream frontend optionally uses
`espeak-ng`; without it some brand names or unusual words may be omitted.

## Discord setup

1. Open your application in the [Discord Developer Portal](https://discord.com/developers/applications).
2. Under **Bot → Privileged Gateway Intents**, enable **Message Content Intent**.
   The client requests Guild Messages and Message Content alongside its existing
   Guilds and Guild Voice States intents. Restart it after enabling the intent.
3. Give the bot View Channels, Send Messages, Read Message History, Connect and
   Speak permissions in the intended text and voice channels.
4. Register the new slash commands with `npm run deploy`, then start the compiled
   bot with `npm run prod` for smooth audio.

Try `@bot สวัสดี ช่วยแนะนำตัวสั้น ๆ`, `/chat message:Hello, please reply in English`,
and a mixed message such as `วันนี้ใช้ Discord ทำอะไรดี`. Follow up in the same
text channel to use the same history; use `/chat-reset` to start fresh.

## Service API and operation

- `GET http://127.0.0.1:8788/health`: loaded model status, CPU device, voices and busy state.
- `POST /synthesize` with JSON `{ "text": "สวัสดี", "voice": "f_young_clear" }`:
  returns a PCM WAV, mono, 16-bit, 24 kHz. Voice is optional; speed is fixed at 1.0.
- Invalid text/voice returns 400, oversize body 413, busy inference 503, failed
  or empty synthesis 500. Health stays responsive during inference.
- `.\scripts\local-voice.ps1 stop` stops only the service recorded by the script.
  Start it again with `start`; stdout/stderr logs are under `.local-voice/`.
- The service binds only to `127.0.0.1:8788`. To run it in the foreground:
  `.\.local-voice\venv310\Scripts\python.exe services\local-tts\server.py`.
- Each Ollama/TTS request has a 120-second timeout. Failures are reported in Thai;
  an existing text answer is kept. Chat never falls back to online TTS.

Speech uses the existing per-guild audio queue and music pause/resume path.
The user's live voice state is checked when speech is queued, when its queue
turn starts and after synthesis, so leaving or moving cannot send speech to a
stale room. A bot already in another room is never moved by chat.

## Validation

```powershell
npm run check
npm run build:all
.\scripts\local-voice.ps1 test
.\.local-voice\venv310\Scripts\python.exe services\local-tts\smoke.py
```

The smoke test blocks outbound Python sockets, loads the local model, generates
Thai/English/mixed speech and calls Ollama through loopback. It writes WAVs and
timings under `.local-voice/smoke/`, and reports peak process RAM on Windows.
Timings vary with hardware and concurrent CPU work; use those measurements
before assessing speed.

On the implementation machine (2026-10-12), the offline smoke loaded Wayu in
8.45 seconds, synthesized short samples in 0.8–4.56 seconds and reached about
1.6 GB peak Python working-set RAM. Real HTTP chat + speech checks in English
and mixed Thai/English completed in 19.5 and 22.6 seconds respectively; synthesis
alone took 2.9 and 6.1 seconds. These are short-sample observations, not a bound
for longer messages. Qwen was running in Ollama on GPU; Wayu stayed on CPU.

Some Qwen/Ollama templates prefill an opening thinking tag despite `think:false`.
The client also supplies `/no_think` and discards reasoning through a returned
closing tag before displaying, remembering or speaking the final answer.

Discord checks still require a real server: verify two users and two text
channels have separate histories; reset history; send enough requests to fill
the waiting queue; stop Ollama/TTS to check Thai errors; leave/move while waiting
and during synthesis; and play music before chatting to confirm it resumes.
No microphone input, dashboard chat UI, or persistent chat history is included.
